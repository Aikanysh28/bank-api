# Bank API

REST API для работы с клиентами банка, их телефонами, счетами и картами.

Стек: .NET 8, ASP.NET Core Web API, Entity Framework Core (SQLite), JWT-аутентификация, Swagger.

## Запуск

```
dotnet run --project BankApi
```

Swagger UI: http://localhost:5080/swagger

При первом запуске создаётся файл базы `BankApi/bank.db`, применяются миграции и создаётся
администратор `admin` / `Admin123!` (секция `SeedAdmin` в `appsettings.json`).

Ключ подписи JWT в `appsettings.json` предназначен только для разработки; в другом окружении
его нужно переопределить (например, переменной `Jwt__Key`, не короче 32 символов).

## Аутентификация и авторизация

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | регистрация пользователя с ролью `Operator` |
| POST | `/api/auth/login` | получение JWT |

Все остальные эндпоинты требуют заголовок `Authorization: Bearer <token>`.
Удаление клиента доступно только роли `Admin`.

## Эндпоинты

| Ресурс | Путь | Операции |
|---|---|---|
| Клиенты | `/api/clients` | GET (список), POST |
| | `/api/clients/{id}` | GET, PUT, DELETE |
| Телефоны | `/api/clients/{clientId}/phones` | GET, POST |
| | `/api/clients/{clientId}/phones/{id}` | GET, PUT, DELETE |
| Счета | `/api/clients/{clientId}/accounts` | GET, POST |
| | `/api/clients/{clientId}/accounts/{id}` | GET, PUT, DELETE |
| | `/api/clients/{clientId}/accounts/{id}/close` | POST — закрытие счёта |
| | `/api/clients/{clientId}/accounts/{id}/deposit` | POST — пополнение |
| | `/api/clients/{clientId}/accounts/{id}/withdraw` | POST — снятие |
| Карты | `/api/accounts/{accountId}/cards` | GET, POST |
| | `/api/accounts/{accountId}/cards/{id}` | GET, PUT, DELETE |
| | `/api/accounts/{accountId}/cards/{id}/block` | POST — блокировка |
| | `/api/accounts/{accountId}/cards/{id}/unblock` | POST — разблокировка |
| Переводы | `/api/transfers` | POST — перевод, GET — история (`accountId`, `page`, `pageSize`) |

### Список клиентов

`GET /api/clients` принимает параметры:

- `search` — подстрока фамилии, имени или отчества;
- `email` — подстрока email;
- `phone` — подстрока номера телефона;
- `birthDateFrom`, `birthDateTo` — диапазон даты рождения;
- `sortBy` — `LastName` (по умолчанию), `Email`, `BirthDate`, `CreatedAt`; `desc` — обратный порядок;
- `page` (с 1), `pageSize` (1–100, по умолчанию 20).

Ответ: `{ items, page, pageSize, totalCount, totalPages }`.

## Бизнес-правила

- **Перевод** возможен только между двумя разными открытыми счетами в одной валюте. Конвертация
  не выполняется: перевод между счетами в разных валютах отклоняется. Овердрафт не допускается.
- В переводе можно указать `cardId` — карту счёта-отправителя. Карта должна принадлежать этому
  счёту, не быть заблокированной и не быть просроченной.
- **Закрытие счёта** возможно только при нулевом балансе и отсутствии активных карт
  (активная — не заблокированная и не просроченная). Закрытый счёт нельзя изменять, пополнять,
  использовать в переводах; к нему нельзя выпускать и разблокировать карты.
- **Удаление счёта** возможно при нулевом балансе и отсутствии истории переводов; иначе счёт
  следует закрыть. **Удаление клиента** возможно, только если у него нет счетов.
- Баланс меняется только пополнением, снятием и переводом. Параллельные изменения одного счёта
  защищены оптимистичной блокировкой (поле `Version`): проигравший запрос получает 409.
- Номер счёта и номер карты генерируются сервером, если не переданы. Email клиента, номер счёта
  и номер карты уникальны; номер телефона уникален в пределах клиента. Уникальность проверяется
  до сохранения и дополнительно гарантируется индексами базы: при одновременных запросах
  с одинаковым значением второй получает 409.

## Ошибки

Ошибки возвращаются в формате Problem Details (RFC 7807):

| Код | Когда |
|---|---|
| 400 | ошибка валидации входных данных |
| 401 / 403 | нет токена / недостаточно прав |
| 404 | ресурс не найден |
| 409 | нарушение уникальности или конкурентное изменение |
| 422 | нарушение бизнес-правила (недостаточно средств, разные валюты, счёт закрыт, карта заблокирована и т. п.) |

Описания методов и коды ошибок каждого эндпоинта видны в Swagger UI.

## Тесты

```
dotnet test
```

- `BankApi.Tests/Domain` — модульные тесты бизнес-правил счёта и карты;
- `BankApi.Tests/Api` — интеграционные тесты: приложение поднимается целиком на временной базе SQLite;
- `BankApi.Tests/Errors` — преобразование исключений в ответы API.

## Структура проекта

```
BankApi/
  Controllers/   контроллеры: только HTTP
  Services/      сценарии: загрузка данных, вызов правил, сохранение
  Domain/        сущности с бизнес-правилами (Account, Card) и перечисления
  Data/          DbContext и миграции EF Core
  Contracts/     DTO запросов и ответов, валидация
  Errors/        исключения и их преобразование в Problem Details
  Swagger/       описание ответов с ошибками в OpenAPI
BankApi.Tests/   тесты
```

Бизнес-правила (перевод, закрытие счёта, блокировка карты) находятся в сущностях `Account` и
`Card`: состояние счёта и карты меняется только через их методы. Нарушение правила — это
`DomainException`, которое превращается в ответ 422.

Новая миграция: `dotnet tool restore`, затем
`dotnet ef migrations add <Name> --project BankApi --output-dir Data/Migrations`.

## Ограничения

- SQLite выбран, чтобы проект запускался без установки СУБД. Поиск через `LIKE` в SQLite
  регистронезависим только для латиницы; для кириллицы регистр учитывается.
